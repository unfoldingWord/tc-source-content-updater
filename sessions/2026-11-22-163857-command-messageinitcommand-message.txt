⏺ The STAGE values (src/index.js:35) are passed as the stage parameter to the
  DCS Catalog Next search API. Each level returns one entry per repo: the most
  bleeding-edge version available, but no less stable than the level you asked
  for. Each level includes everything the levels above it would return.

  Constant: STAGE.PROD
  Value: prod
  What DCS returns for each repo: Only full (non-pre-release) releases. Repos
    with no full release are left out.
  Aligned Bibles today: 65
  ────────────────────────────────────────
  Constant: STAGE.PRE_PROD
  Value: preprod
  What DCS returns for each repo: The newest pre-release if there is one,
    otherwise the prod release.
  Aligned Bibles today: 69
  ────────────────────────────────────────
  Constant: STAGE.DRAFT
  Value: draft
  What DCS returns for each repo: Meant to be: a draft release if there is
    one, otherwise preprod or prod.
  Aligned Bibles today: HTTP 422 (the API rejects it)
  ────────────────────────────────────────
  Constant: STAGE.LATEST
  Value: latest
  What DCS returns for each repo: The default branch (e.g. master) if it is a
    valid resource container, otherwise the newest release. This also picks up
    repos that have never been released.
  Aligned Bibles today: 285

  You can see the fallback in the latest results I fetched earlier. Each entry's
  stage field shows what was actually returned: 233 came from latest (the
  default branch), 49 from prod and 3 from preprod. Also, ref_type is branch for
  default-branch entries and tag for releases, which decides whether the raw
  file URLs use /raw/branch/... or /raw/tag/....

  How this library uses them:
  - Defaults differ by entry point:
    - Updater.searchCatalogNext() / apiHelpers.searchCatalogNext default to
      LATEST (apiHelpers.js:421).
    - updateCatalog() / getCatalog() default to PROD for the main search
      (apiHelpers.js:293), which is what translationCore normally uses. The
      extra query for the legacy Door43-Catalog owner always uses LATEST
      (apiHelpers.js:283).
  - Only PRE_PROD turns on "pre-release mode" (resourcesDownloadHelpers.js:145
    isStagePreRelease). In that mode a flag is stored in the resources manifest,
    and old resource versions are not deleted after a download. That way a user
    who tries preprod content keeps their production versions. LATEST and DRAFT
    don't set this flag, even though they can return content that isn't in
    production.
  - After a download, the stage of the version that came back is written into
    that resource's manifest.json (resourcesHelpers.js:401-409).

  Two things that look off:
  1. STAGE.DRAFT doesn't work against the current DCS server (422), even though
     it's documented and exported. It should be removed, or the API docs should
     be checked for the current name.
  2. LATEST isn't treated as pre-release, even though it can return unreleased
     master branches. If translationCore ever passes LATEST to updateCatalog,
     old versions would be deleted the same way as for prod. That may be fine if
     it's only used for searching, but it's worth knowing.
